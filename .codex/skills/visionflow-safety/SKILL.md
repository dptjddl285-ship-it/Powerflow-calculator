# VisionFlow Safety Guide

이 Skill은 VisionFlow 코드베이스를 다룰 때 기존에 구현된 핵심 자산(YOLO 체크포인트, CV 기하 엔진, 위상 추적기, Flutter UI)을 훼손하지 않고 안전하게 수정하기 위한 표준 작업 절차를 정의한다.

---

## 1. 작업 시작 전 (Pre-Execution Inspection)

1. **Repository Root 확인**: 항상 현재 작업 경로가 프로젝트 루트(`전력계통대회2`)인지 확인한다.
2. **`git status` 점검**: 작업 전 워크스페이스에 기존 사용자의 미커밋 변경사항이 있는지 확인한다.
3. **현재 Branch 확인**: 현재 활성화된 브랜치를 확인하고 임의로 브랜치를 전환하거나 force checkout하지 않는다.
4. **작업 대상 파일 목록 한정**: 이번 작업에 꼭 필요한 파일만 명확히 특정한다.
5. **사용자 변경사항 보호**: 이미 수정되어 있는 코드는 사용자의 의도된 작업일 수 있으므로 임의로 원복(revert)하거나 덮어쓰지 않는다.
6. **작업 범위 분리**: 사용자가 작업한 변경과 Agent가 작성할 변경 영역을 명확히 구분한다.

---

## 2. 작업 중 (Safe Implementation Principles)

* **최소 범위 수정**: 필요한 부분만 외과수술식으로 최소 수정하며, 파일 전체를 불필요하게 재작성하지 않는다.
* **대규모 리팩터링 금지**: 요청되지 않은 디렉토리 구조 변경, 아키텍처 전면 개편, 클래스/함수 이름 변경을 금지한다.
* **핵심 에셋 삭제 금지**: `backend_api/models/2026_07_30_coslr.pt` 등 모델 파일, 테스트 이미지, 체크포인트를 절대 삭제/변경하지 않는다.
* **엔진 중복 생성 금지**: 기존 Vision 파이프라인(`vision_logic.py`, `electrical_topology.py`)을 복제하여 새로운 별도 엔진을 만들지 않고 기존 파이프라인을 그대로 활용한다.
* **Adapter 패턴 우선**: 기존 함수와 새로운 인터페이스 간의 차이는 래퍼(Adapter) 함수를 통해 연결한다.
* **실제 Call Path 사용**: 유사한 함수나 실험 파일이 있더라도 실제 `main_server.py` → `adaptive_vision_pipeline.py`에서 호출되는 코드를 기준으로 작업한다.
* **파괴적 쉘 명령 금지**: `git reset --hard`, `git clean -fd`, `git checkout .` 등 복구 불가능한 명령을 사용하지 않는다.

---

## 3. 작업 후 (Post-Execution Verification)

1. **수정 파일 목록 점검**: 계획된 파일 외에 의도하지 않은 파일이 변경되지 않았는지 확인한다.
2. **`git diff` 상세 검토**: 디버깅용 임시 코드(`print`, `console.log`, 하드코딩된 값)가 남아 있지 않은지 확인한다.
3. **단위 테스트 실행**: 변경 후 [visionflow-regression](../visionflow-regression/SKILL.md) 절차에 따라 관련 테스트를 실제 실행한다.
4. **회귀(Regression) 확인**: 기존 객체 검출 및 결선 추적 계약이 손상되지 않았는지 점검한다.
5. **투명한 결과 보고**: 실패한 테스트를 숨기거나 건너뛴 테스트를 `PASS`로 거짓 보고하지 않는다.
6. **사용자 작업 보존 확인**: 기존 사용자의 변경사항이 손실 없이 그대로 보존되었는지 최종 점검한다.
7. **최종 `git status` 확인**: 최종 상태를 출력하고 커밋 여부는 사용자의 명시적 요청이 있을 때만 진행한다.
